Installation

Requirements

  • PHP 8.3, 8.4, or 8.5, with the mbstring and tokenizer extensions. Most PHP builds include both, and Composer reports a missing one.
  • Composer.
  • Python 3 with the venv module. On Debian and Ubuntu that module is the python3-venv package.
  • macOS or Linux.

The kernel runs in a Python environment with ipykernel 7.0 or later. The current ipykernel release requires Python 3.11 or later. juphyter install uses an existing environment that has ipykernel, or builds one.

Optional:

Feature Needed for
The pcntl PHP extension Interrupting a running cell with the stop button. Without it the stop button does nothing.
Quarto Rendering .qmd documents. CI tests Quarto 1.10.18.
vl-convert Static images of phiz plots in PDF and Word output. See Output formats.
phibble, phplyr, and phiz Data frame tables and charts. See The phpstats packages.

Install juphyter

Install juphyter for your user and put Composer’s bin directory on PATH:

composer global require phpstats/juphyter
export PATH="$(composer global config bin-dir --absolute):$PATH"

Register the kernel

juphyter install --create-venv ~/.venvs/juphyter
export PATH="$HOME/.venvs/juphyter/bin:$PATH"
  • juphyter install registers a kernel named php for your user, so one install serves notebooks and documents in every directory.
  • It uses the Python environment that owns the jupyter command on PATH when that environment has ipykernel. Otherwise it builds an environment with JupyterLab at the --create-venv path. It changes no existing Python installation.
  • The kernel records absolute paths to the PHP binary, the Python interpreter, and juphyter. The PHP is the one running juphyter install, recorded as the first path on PATH that leads to it, such as /opt/homebrew/bin/php.
  • The second export puts the environment first on PATH, so jupyter lab and quarto render find it. When juphyter install used an existing environment, the directory does not exist and the line has no effect.

Without Composer’s bin directory on PATH, Composer can run the same command:

composer global exec juphyter -- install --create-venv ~/.venvs/juphyter

The command prints the kernelspec, the PHP, the Python, and the engine it recorded. When Quarto is installed and the Python Quarto would use has no Jupyter, it also prints a warning with the export line that fixes it. The kernel is still registered.

Check the installation

juphyter doctor

juphyter doctor checks juphyter’s files, the PHP that runs the cells, the Python for the kernel, the Python Quarto will use, and every kernel juphyter registered. It changes nothing, and it ends with two summary lines:

Line Meaning
JupyterLab: ready, with php. The kernel is registered, and its PHP, Python, and juphyter files run.
Quarto: ready. Quarto will run a Python that has Jupyter.
Quarto: not installed. quarto is not on PATH. Quarto is needed only for rendering .qmd documents.
Quarto: not ready. Quarto is installed and its Python lacks Jupyter or does not run. The report ends with the export line that fixes it.

A line marked fail makes the command exit 1, and Quarto: not ready. is a failure. A line marked warn, such as a missing pcntl, does not change the exit code.

Run juphyter doctor again after upgrading PHP or Python, or after removing a project or an environment. Troubleshooting covers the failures it reports.

Keeping the PATH entries

Both export lines last until the shell closes. To keep the juphyter command in new shells, add Composer’s bin directory to your shell startup file. This appends to ~/.zshrc. Use ~/.bashrc for bash.

echo "export PATH=\"$(composer global config bin-dir --absolute):\$PATH\"" >> ~/.zshrc

Putting the Python environment in a startup file makes it the python3 for every program, including every Quarto project on the machine. Python interpreters and editors describes how to select it per editor workspace, per shell, or per Quarto project instead.

The phpstats packages

juphyter does not depend on phibble, phplyr, or phiz. A notebook inside a Composer project that requires them can use them with the php kernel. To use them in notebooks outside any project, install them globally and register a second kernel that loads Composer’s global autoloader:

composer global require phpstats/phibble phpstats/phplyr phpstats/phiz
juphyter install --name phpstats --display-name "PHP (phpstats)" \
  --autoload "$(composer global config home)/vendor/autoload.php"

Documents name that kernel as jupyter: phpstats, and JupyterLab lists it as “PHP (phpstats)”. A kernel installed with --autoload always loads the autoloader it names, even for a notebook inside a Composer project, which is why it has its own name.

Which classes a notebook sees

The kernel starts in the notebook’s directory, looks upward for vendor/autoload.php, and loads the first one it finds. A notebook anywhere inside a Composer project can use that project’s classes and packages.

Two settings replace that search. The more explicit one wins.

  1. JUPHYTER_AUTOLOAD in the kernel’s environment. juphyter install --autoload PATH records it in the kernel.
  2. A juphyter.json in the notebook’s directory or any directory above it.

A juphyter.json can also set the memory limit and the include path:

{
  "autoload": "vendor/autoload.php",
  "memory_limit": "512M",
  "include_path": "lib"
}

Relative paths resolve against the directory that holds juphyter.json.

Installing into one project

juphyter can also be a development dependency of a project:

composer require --dev phpstats/juphyter
vendor/bin/juphyter install --name myproject
  • The kernel is still registered for your user, and it runs that project’s copy of juphyter.
  • Without --name, a second project’s install replaces the first project’s php kernel, and the command reports it as Replaced.
  • Deleting the project’s vendor directory breaks the kernel, which juphyter doctor reports.

Several PHP versions

Give each kernel its own name:

juphyter install --name php83 --php /opt/homebrew/opt/php@8.3/bin/php
juphyter install --name php85 --php /opt/homebrew/opt/php@8.5/bin/php

JupyterLab then lists “PHP 8.3” and “PHP 8.5”. An absolute --php path is recorded as written. A bare name such as php8.4 is resolved to an absolute path, because a kernel cannot rely on PATH.

Where the kernel is registered

juphyter install writes a kernelspec, the kernel.json file Jupyter reads to start a kernel, into the per-user Jupyter data directory. Every Jupyter installation on the machine searches that directory.

Platform Directory
macOS ~/Library/Jupyter/kernels
Linux $XDG_DATA_HOME/jupyter/kernels, or ~/.local/share/jupyter/kernels

JUPYTER_DATA_DIR replaces that directory, and --prefix PATH writes under PATH/share/jupyter instead.

juphyter uninstall --name NAME removes a kernel that juphyter registered. It refuses to remove a kernel of the same name that something else wrote, and so does a reinstall.

Options

juphyter install --help lists every option:

Option Meaning
--name NAME The kernel’s name, which documents use in jupyter: NAME. Default: php.
--display-name TEXT The label JupyterLab shows. Default: the PHP version, such as PHP 8.5.
--php PATH The PHP binary that runs cells. Default: the PHP running juphyter install.
--python PATH The Python that hosts the kernel. Default: the one that owns jupyter on PATH.
--prefix PATH Write under PATH/share/jupyter.
--autoload PATH Load this autoloader instead of searching above the notebook.
--create-venv PATH Where to build a Python environment when none can host the kernel. Without it, the command asks, and builds one at ~/.venvs/juphyter when there is no terminal to ask.

juphyter --version prints the installed version and the PHP running it.
